# M1-03 — проба: шесть уровней-головоломок

**Цель.** Проба мира 1 (0.0.8, 10.10): после двух-трёх обучающих уровней играть слишком легко, а больше ям, дверей и лазеров — не усложнение. Решение Никиты 10.10 (GDD, раздел «Решения», строка «Сложность уровней»): сложность растёт головоломкой — надо придумать, где и как погибнуть, чтобы тело стало нужной деталью; рост плавный. Эта задача добавляет шесть уровней нового подхода отдельным набором `pz`, мир 1 не меняется. Никита играет их по ссылке с `?set=pz` и решает, переделывать ли по ним мир 1.

**Что изменится в игре.** По адресу игры с `?set=pz` — шесть новых уровней: «Подставка», «Мёртвый груз», «Дрожь», «Мост в воздухе», «Две пилы», «Наверху», с названиями и подсказками на русском и английском. Без `?set` игра, как и прежде, идёт по миру 1. Версия 0.0.9.

Перед началом прочитай `CLAUDE.md`, `data/README.md` (уровни, миры, решения бота) и в `docs/GDD.md` раздел «Уровни и миры» — правила «Как строим уровни» и таблицу «Головоломки — проба».

**Проверка до передачи.** Уровни построены Claude 10.10.2026 и разобраны ботом с запасом по всем состояниям уровня до глубины пара (разбор — инструмент в песочнице Claude, в репозитории его пока нет). Пар в файле — число бота, строгий бот находит те же числа. «Простой игрок» — в каждой жизни не жмёт или прыгает, чтобы пройти подальше, — пара не берёт ни на одном уровне (в мире 1 он берёт его в 10 уровнях из 15). Решение с паром одно, в «Подставке» — три. В каждой жизни решения — не больше трёх прыжков (предел бота), первые две клетки после старта — безопасный пол. Код и уровни прогнаны в песочнице поверх M1-02 (состояние ноутбука после коммита «M1-02: мир 1, Карамельный цех — 15 уровней»): `npm run solve` — около 3 минут, вывод — как в §4; `npm run check` зелёный, Vitest — 22 файла, 141 тест; Playwright — 15 passed, 1 skipped. Из 7 намеренных поломок (пар и карта уровня, нет решения, нет строки набора, файл набора не подключён, нет строки подсказки, нажатие решения на 1/60 с позже) ловятся шесть: `npm run test` — все, пропуск строки — ещё и `npm run data`; сдвиг нажатия на 1/60 с решение не ломает — у него запас, это не ошибка. Пробная сборка независимым исполнителем по этому тексту (10.10, около 14 минут): все файлы совпали с эталоном байт в байт, вывод `npm run solve` и `data/solutions/pz.json` — как в §4, `npm run check` зелёный; по её итогам уточнено, какие тесты красные до шага 3, и что файл уровней кончается переводом строки.

**Условие.** M1-02 сделана (в `docs/tasks/README.md` у M1-02 стоит «сделано …»). Если нет — остановись и напиши об этом в отчёте.

## 1. Файлы

Как это устроено. Набор уровней — строка в `data/worlds.csv` и файл `data/levels/pz.txt`, подключённый в `src/data.ts`; игра берёт его по адресу с `?set=pz` (M1-02). Названия и подсказки — строки `translations/strings.csv`. Решения бота для набора пишет `npm run solve` в `data/solutions/pz.json`, а `tests/unit/solutions.test.ts` повторяет их ядром, как решения мира 1. В `tools/solve.ts` набор `pz` добавлен к наборам, где решение короче 15 с — норма: уровни пробы идут 6–15 с.

Файл §1.1 — дословно целиком, строки §1.2 и §1.3 — дословно в конец файла. В остальных — правки «было → стало»: блок «было» встречается в файле ровно один раз, его надо заменить блоком «стало», остальное в файле не трогать.
