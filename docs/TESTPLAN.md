# TESTPLAN — «Желейный легион» (v1.0, 09.10.2026)

Шесть уровней проверки. Ошибка, найденная на любом уровне, сначала становится тестом, который падает, потом исправляется.

## 1. Тесты ядра — Vitest (`npm run test`)

- На каждый модуль `src/core/` — файл `tests/unit/<модуль>.test.ts`. Новая механика приходит с тестом, который без неё падает.
- Время — только через шаги `run.step(dtMs)` или `FixedStep.advance`; для модулей, которые считают время, — тест на независимость от частоты кадров (30, 60 и 144 кадра в секунду дают одно и то же).
- **Сверка с прототипом.** Физика и застывание переносятся из `docs/research/prototype.html` дословно, поэтому числа в тестах-сторожах (высота и дальность прыжка, клетки тел на уровнях прототипа при заданных нажатиях) получены прогоном самого прототипа и должны совпадать до 1e-6 — или до клетки, где задача называет отличие.
- Числа баланса в тестах механики берутся из `DATA`, а не вписываются: правка таблицы не должна ломать тесты механики. Исключение — тесты-сторожи с числами из задачи (`data.test.ts`, сверка с прототипом).
- Уровни для тестов механики — маленькие карты прямо в тесте (тот же формат, что в `data/levels/`), чтобы правка уровней не ломала тесты правил. Тесты-сторожи на уровнях прототипа `p-01` … `p-06` (сверка с прототипом, прогоны без нажатий) допустимы: задача, которая меняет эти уровни, переписывает и их числа.
- Предел времени `npm run test` — 30 с на ноутбуке; дольше — в `npm run solve`.

## 2. Проверка данных (`npm run data`)

`tools/data-check.mjs`: заголовки и типы таблиц, обязательные константы, уникальность, ссылки (мир → файл уровней, уровень → строки названия и подсказки), карты уровней (13 строк по 24 знака, известные знаки, один старт на земле или плите, один флаг, дверь только вместе с плитой своей пары — M1-01), строки ru и en у каждого ключа, межстраничная не чаще раза в 180 с. Входит в `npm run check` первой. На этапе 0 проверено 22 намеренными поломками — все пойманы.

## 3. Смоук и сценарии собранной игры — Playwright (`npm run e2e`)

- Две раскладки: `desktop` 1280 × 720 и `phone` 412 × 915. Игра запускается без ошибок в консоли, раскладка верная, площадке ушёл `loadingFinished`.
- Смоук поднимает предпросмотр сборки (`npm run preview`) на порту 4273, а не на 4173 по умолчанию Vite: там может отвечать предпросмотр другого проекта, и смоук молча проверил бы чужую сборку (M1-01).
- Снимки — `build/shots/<задача>_<раскладка>.png` от задачи, которая меняет экран (этап 0 и M0-01 — заглушка `s0_*`, с M0-02 — `m0-02_*`, с M1-02 первый экран — `m1-02_*`: первый уровень мира 1); их смотрят глазами при приёмке.
- Игра по умолчанию идёт по миру 1; сценарии на уровнях прототипа открывают её с `?set=proto` (M1-02).
- Сценарии задач — через `window.__game` (команды и чтение состояния) и настоящие нажатия `page.mouse`, `page.touchscreen`, `page.keyboard`, когда проверяется сам ввод.
- Headless-браузер рисует программно и бывает медленным (единицы кадров в секунду): сценарии ждут условия (`waitForFunction`, `expect.poll`), а не фиксированное время; правила гоняются через `advance(ms)`, паузы интерфейса — unit-тестами.

## 4. Проба Никиты (ворота M0, мир 1)

1. Сборка по ссылке (`npm run publish`) или `npm run dev` по Wi-Fi (адрес Network из вывода Vite; VPN на ноутбуке выключить).
2. Шесть уровней прототипа на телефоне в портрете, на телефоне в горизонтали и на ПК.
3. Никита отвечает тремя словами на каждое: удобно ли прыгать, понятно ли, где застынет тело, видно ли головоломку в портрете (камера и карта уровня).
4. Замечания — в GDD комментариями или в чат; решения записываются в GDD (раздел «Решения»).
5. Мир 1 (после M1-02): 15 уровней «Карамельного цеха» на телефоне; Никита пишет, где застрял, что непонятно без слов, какие уровни слишком лёгкие или трудные. Ворота M1 — после сохранения, карты миров и бота «человек».

## 5. Бот-решатель и бот «человек» (с M0-04)

- `npm run solve`: для каждого уровня — пар бота с запасом (с M0-05: у каждого нажатия окно не меньше 0,1 с с тем же исходом жизни, короткий тап — любой длины до 0,1 с; числа — `par_window_s` и `par_tap_s` в `data/constants.csv`), строгий пар (точность 1/60 с), время решения, запас нажатий («окно»: сколько подряд шагов годятся для каждого нажатия в своей жизни, не меньше 6 = 0,1 с; «12» — это 12 и больше), сколько перебрано. Код выхода 1 — пар в файле уровня не равен найденному или уровень не решён. Строгий бот ищет только решения с меньшим числом гибелей, чем у бота с запасом (M1-02): решение с запасом — тоже решение строгого бота, поэтому строгий пар не больше. Замечание «решение короче 15 с» — для миров 2–4; прототип и учебный мир 1 короче (GDD «Уровни и миры», «Как строим уровни»).
- Решения бота с запасом пишутся в `data/solutions/<набор>.json`. `tests/unit/solutions.test.ts` (в `npm run test`) повторяет каждое решение ядром и сверяет пар, отпечаток карты и запас (окна и длины тапов): правка правил, которая ломает уровень, или правка карты без нового `npm run solve` роняет тест.
- Сторож самого бота — `tests/unit/robust.test.ts`: на быстрых уровнях прототипа (p-01, p-02, p-03, p-05) оба бота находят ровно записанное в `data/solutions`; правка бота без нового `npm run solve` роняет тест.
- Бот «человек» (с M1): реакция 0,2–0,35 с, ошибка нажатия ±50 мс; мерит время и гибели на уровень. Ворота M1: мир 1 за 12–18 минут.

## 6. Живые проверки

- После каждой вехи — сборка по ссылке, проба Никиты на телефоне (60 кадров в секунду, всё нажимается, окна помещаются).
- M5 — пробный запуск: песочница Playgama, CrazyGames Basic Launch (ориентиры: 10+ минут, D1 10–15 %), Яндекс.

## Интерфейс до вехи арта (M3)

Окна — рабочая заготовка: окно помещается на экран в обеих раскладках, всё нажимается, случайного действия двойным нажатием нет (неактивная кнопка или пауза ввода). Тест окна — поведение и «окно не больше экрана в обеих раскладках»; пиксельные проверки вида не пишем.
