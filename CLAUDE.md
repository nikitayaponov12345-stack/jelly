# CLAUDE.md — правила для Claude Code в проекте «Желейный легион»

## Что это
Браузерная 2D-игра: раннер на одну кнопку, где каждая погибшая желейка застывает и становится частью уровня — заполняет яму, держит плиту, перекрывает лазер, служит ступенькой. Уровень — один экран 24 × 13 клеток. Площадки первого выпуска: песочница Playgama → CrazyGames → Яндекс Игры через Playgama Bridge; Poki — отдельной сборкой без покупок.

## Документы
- `docs/GDD.md` — правила игры и числа (выгрузка Claude Doc «Желейный легион: GDD»; правится в Claude Doc, сюда — новой выгрузкой).
- `docs/ARCHITECTURE.md` — устройство кода и инварианты. `docs/ROADMAP.md` — вехи и задачи. `docs/TESTPLAN.md` — как проверяем.
- `data/README.md` — таблицы, формат уровней и формулы между ними.
- `docs/research/prototype.html` — прототип из отчёта о нишах: образец физики и правил застывания. Ядро M0 переносит его формулы дословно; отличия перечислены в GDD и в задачах.
- `docs/tasks/` — задачи и их статус (`docs/tasks/README.md`). `docs/research/README.md` — откуда идея и решения Никиты.

## Команды
- `npm run dev` — сервер разработки: http://localhost:5173, адрес для телефона Vite печатает строкой Network.
- `npm run data` — проверка таблиц `data/*.csv`, уровней `data/levels/*.txt` и строк `translations/strings.csv`.
- `npm run test` — тесты Vitest (`tests/unit`).
- `npm run build` — проверка типов, сборка в `dist/` и отчёт о размере (бюджет — 3 МБ сжатых данных).
- `npm run e2e` — смоук Playwright по собранной игре в двух раскладках, снимки в `build/shots/`.
- `npm run check` — всё вместе. Перед отчётом по любой задаче он должен быть зелёным.
- `npm run publish` — сборка по ссылке для телефона: отправляет `dist/` в открытый репозиторий `jelly-play` (GitHub Pages). Запускает Никита; Claude Code проверяет только `npm run publish -- --dry-run`.

## Устройство
- `src/core/` — правила игры: чистый TypeScript без PixiJS, DOM, localStorage, часов браузера и `Math.random()`. Время — только шаги `FixedStep` (60 в секунду игрового времени); внутри ядра единицы — клетки и секунды.
- Координаты уровня — клетки: столбец `c` слева направо 0…23, ряд `r` сверху вниз 0…12; точка `(x, y)` — в клетках, `y` растёт вниз; клетка `(c, r)` занимает `[c, c+1) × [r, r+1)`.
- `src/data.ts` — таблицы и файлы уровней для игры и тестов (через `?raw`).
- `src/game/` — отрисовка PixiJS и ввод (нажатия → команды ядра); правил не решает.
- `src/ui/` — строка счёта и окна: вёрстка поверх холста.
- `src/platform/` — слой площадки: с SDK площадок игра говорит только через интерфейс `Platform`.
- `src/debug.ts` — `window.__game` для тестов и ботов: не удалять, расширять по задачам.

## Правила
1. Всё, что зависит от времени (бег, прыжок, лазеры, возрождение, лопание), считается в игровом времени шагами по 1/60 с, а не в кадрах.
2. Числа баланса — только из `data/constants.csv`, уровни — только из `data/levels/*.txt`, не из кода. После правки — `npm run data`.
3. На каждый модуль ядра — тесты Vitest; новая механика приходит с тестом, который без неё падает. Числа в тестах механики берутся из `DATA`, а не вписываются (кроме тестов-сторожей с числами из задачи).
4. Файл — не длиннее 400 строк.
5. Физика и застывание — как в прототипе: порядок действий в шаге и формулы не «улучшать». Отличия от прототипа — только те, что названы в GDD и в задаче.
6. Строки интерфейса — через `translations/strings.csv` (ru, en); текст в код окон не вписывать.
7. Ввод — командами ядра (`press`, `release`, `restart`): бот и тесты подают те же команды, что и палец.
8. В коде игры нет сетевых запросов, кроме SDK площадок в адаптерах.
9. Интерфейс до вехи арта (M3) — рабочая заготовка: помещается на экран в обеих раскладках, всё нажимается, случайного действия двойным нажатием нет. Вид и пиксели не вылизывать.

## Порядок работы
- Задачи лежат в `docs/tasks/`, статус — в `docs/tasks/README.md`. Делать только то, что написано в задаче; спорное — в отчёт, а не в код.
- В конце задачи: `npm run check`, строка статуса «сделано ДД.ММ» в `docs/tasks/README.md`, отчёт: что сделано, итоги `npm run check`, что не получилось и почему.
- Не коммитить и не пушить: это делает Никита.
- Windows и PowerShell: пути с пробелами — в кавычках; в npm-скриптах нет bash-синтаксиса.
